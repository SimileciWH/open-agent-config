# Open Agent Config AI Documentation

这是仓库的渐进式 AI 知识层。它不是源码副本，而是把任务路由到正确源码、符号、测试和风险证据的可追溯索引。

## 使用顺序

```text
L0 总览 → L1 架构 → 目标 L2 模块卡 → 对应 L3 剧本 → 必要的 L4 证据
```

- L0：每个任务都先读取，确认仓库边界、运行入口和当前支持矩阵。
- L1：涉及跨模块影响时读取，确认扫描、存储、写入、UI 和运行时边界。
- L2：只读取目标任务直接涉及的模块卡。
- L3：开始实施前读取对应的修改和验证剧本。
- L4：遇到风险、失败签名或最终验收时读取 Golden QA 和证据记录。

## 文档与源码的关系

源码是行为事实的唯一来源，`ai-docs/` 是导航和验证合同。模块卡中的每个关键事实必须指向稳定锚点：

```text
relative/path/to/file::symbol
```

行号可以作为辅助证据，但不能作为唯一锚点。每张卡必须记录 `verified_commit`、状态、验证日期和已知缺口。

## 状态定义

- `draft`：已建立结构，但源码或行为证据未完成。
- `static-verified`：已按当前源码、配置和符号完成静态核验。
- `runtime-verified`：静态核验完成，并通过相关测试或运行态验证。
- `stale`：源码锚点、行为或提交证据已经变化，需要重新核验。

## 维护硬规则

任何源代码、测试、配置、CI、发布脚本或用户行为变更，都必须在同一变更集中更新受影响的 L0-L4 文档。详情见仓库根目录的 `AGENTS.md` 和 `WORKFLOW.md`。
