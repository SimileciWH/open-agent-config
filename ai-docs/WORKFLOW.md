# AI Docs 工作流

## 修改前

1. 读取 `ai-docs/README.md`、`INDEX.md` 和对应 L2/L3/L4 文档。
2. 用 `MAP.json` 确认源码边界、调用方和测试入口。
3. 在计划中列出受影响模块卡和稳定锚点。
4. 如果模块卡不存在，先创建模块卡再修改代码。

## 修改中

- 保持源码和模块卡在同一变更集中更新。
- 新增 Agent 时同时检查 Rust 注册、前端排序、能力模型、扫描、部署、运行时入口和测试。
- 修改配置格式时记录原始格式、读取格式、写入格式、未知字段保留策略和 secret 处理。
- 不用文档推测替代源码事实；未知内容标记为 `TBD` 或 `unverified`。

## 修改后

1. 更新受影响的 L2 卡片。
2. 更新相关 L3 剧本和 L4 Golden QA。
3. 重建 `INDEX.md`、`MAP.json`、`COVERAGE.md`、`SYNC_LOG.md`（如果模块、锚点、覆盖或验证状态变化）。
4. 执行 `npm run check:ai-docs`。
5. 执行最窄的相关测试，再执行完整测试和构建。
6. 在 `SYNC_LOG.md` 记录提交、测试命令、结果和未验证项。

## 过期判定

出现以下任一情况，模块卡必须标记为 `stale` 或重新验证：

- 源文件移动、删除或主要符号重命名。
- Adapter 注册列表、前端 `AGENT_ORDER` 或能力字段变化。
- 配置格式、默认路径、scope 语义或 enable/disable 机制变化。
- 测试命令、CI 门禁或发布目标变化。
- 当前实现与卡片描述不一致。

## 提交要求

代码改动和对应 AI Docs 改动必须在同一变更集内。不能先提交代码、以后再补卡片，也不能以“文档不影响功能”为理由跳过同步。
